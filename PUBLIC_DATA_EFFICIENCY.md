# Public ticker intake efficiency and safety

The runtime default public ticker reader now shares a pending transport request among concurrent callers for the same allowlisted BTC/ETH/SOL market. Different markets proceed independently. At most one runtime transport per product is pending in this process; this is not a distributed feed, streaming subscription, cross-venue attestation or broker entitlement. The default GET-only transport still rejects redirects and nonmatching response URLs before body access, uses its existing four-second socket timeout and 65,536-byte body limit, and validates identity, prices and exchange time.

A follower waits at most five seconds, then fails without spawning a replacement or cancelling the owner. Completion, expected transport errors and unexpected leader exceptions all signal followers and release the slot. An expected failure never returns old data or a fabricated quote. A later explicit reader may try again; this adds no automatic retry loop or circuit breaker. Socket timeouts are not a hard overall network deadline; a slow owner can retain its slot while followers time out.

The existing cache window remains strictly less than three seconds. Reuse requires both wall and monotonic ages within that window and the existing exchange-age limit, with wall/monotonic drift no greater than one second and no clock regression. Runtime transport publication also checks wall/monotonic continuity. Every follower samples its own clocks after waking and rechecks the result. Original receipt/exchange timestamps and receipt-time age are preserved, never relabeled as a new observation. Clock changes, stale observations and failed fetches fail for review rather than extending cached life. The forward runner retains its stricter post-lock execution checks. Shared returns represent the same source observation, never independent market confirmations or additional evidence of predictive skill.

Readers receive independent dictionary copies. Injected transports never consume or populate default cache entries or flights. Explicit fixture clocks use an isolated cache clock mode, never join runtime flights or contribute to runtime counters. Private cache slots remain capped by the three fixed products; counters have a fixed shape. No disk, cloud or order state is introduced. A paper throttle cut does not cancel a research reader sharing its request; the runner’s own stop and durable halt still prevent execution when the shared fetch finishes.

`GET /api/public-data/efficiency` returns only copied process-local aggregate counters and configured limits, with Cache-Control: no-store. It neither fetches nor removes cache entries, reads account data, touches storage, starts models or trades. The cached-products count is retained runtime cache slots, not a freshness guarantee. Success timings cover this reader’s transport/parse path only; cache hits and shared returns are separate. No observed quote, exception string, key or user-entered value appears. Counters reset on process restart and have no reset/write API.
