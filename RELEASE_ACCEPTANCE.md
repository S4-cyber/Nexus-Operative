# Nexus Operative release acceptance

Current build: **0.118.0 prerelease**. Production 1.0 remains blocked. This checklist records evidence scope, not runtime permission. No claim that an environment is perfect or a strategy will be profitable follows from passing these checks.

## Repeatable trials

Run from a source checkout with the project dependencies installed:

```sh
python -m nexus.release_trials --output release-trial-evidence/report.json
python -m pytest -q
python -m compileall -q nexus tests tools
```

The trial command uses separate temporary child-process data roots and never starts the installed account, reads actual credentials, connects a broker or requests actual prices. It stops on child failure, malformed/incomplete reports, accounting disagreement or unsupported authority claims. Its report fingerprints Python source, tests, tooling, workflows, package/installer metadata and Portal HTML before and after execution; changing those inputs invalidates the run. The fingerprint is a reproducibility aid, not a signature or source attestation. Generated reports and documentation are excluded to avoid self-reference. Machine/Python/SQLite versions and local timings are recorded. An interrupted command or missing report is not a pass.

## Verify saved evidence before considering a release

Run `python -m nexus.release_evidence validation/release_trials_0_118_0.json` from the matching source checkout. The checker bounds and strictly parses the report, requires the current version, exact source fingerprint, all fourteen expected profiles and retained false authority flags, then reruns every profile's acceptance assertions and rechecks source stability. It emits only an allowlisted summary and the supplied report hash; it does not rerun trials or open account storage. Changed source bytes, including line endings, invalidate the match; never edit a fingerprint to bypass a failed check.

The safety workflow revalidates its saved report. Windows distribution creation runs and validates its own offline trials, includes `release-trial-evidence.json` in the distribution and hashes it in `artifact-manifest.json` alongside both binaries. Verify the manifest first, then verify the report from the exact source checkout. Matching hashes are not signatures, authenticated CI provenance or proof the workload actually ran. A self-consistent fabricated report remains possible; workflow results and independent acceptance still matter. A successful offline evidence check always retains production/native/provider/market/funds/release approval flags as false and cannot close the open gates above.
